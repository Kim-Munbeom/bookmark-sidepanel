# 북마크 사이드패널 확장 프로그램 설계

- 날짜: 2026-09-14
- 상태: 승인됨 (구현 계획 단계로 이관)

## 배경

Chrome 146부터 네이티브 세로 탭 정렬 기능이 제공되지만, 북마크는 여전히 서드파티 확장 프로그램(예: Bookmark sidebar)에 의존해야 한다. 해당 확장 프로그램은 콘텐츠 스크립트로 페이지 위에 사이드바를 오버레이하는 방식이라, 왼쪽으로 배치하면 페이지 레이아웃이 제대로 리사이즈되지 않고 겹치는 문제가 있다.

## 목표

네이티브 세로 탭과 유사한 사용성으로 북마크를 조회/검색/편집할 수 있는 확장 프로그램을 `chrome.sidePanel` API 기반으로 만든다. Side Panel은 브라우저의 실제 UI 영역이라 열리면 페이지 뷰포트가 정상적으로 줄어든다 (DevTools 도킹과 동일한 원리).

## 범위 (v1)

포함:
- 북마크 폴더 트리 조회 (펼침/접힘)
- 북마크 클릭 시 새 탭에서 열기
- 제목/URL 검색(필터링)
- 북마크 추가(현재 탭 저장) / 삭제 / 드래그앤드롭 이동
- 다른 경로(브라우저 기본 북마크바 등)에서의 변경 실시간 반영

제외 (v1에서는 하지 않음):
- 마스크 색상/아이콘 크기/폰트 크기 등 사용자 커스터마이징 설정 화면
- 폴더 펼침/접힘 상태의 영구 저장 (세션 내에서만 유지, 재오픈 시 초기화)
- 별도 작업 로그 파일 (git 커밋 히스토리 + 계획 문서로 추적)

## 알려진 플랫폼 제약 (설계로 해결 불가능한 것들)

- 확장 프로그램은 Chrome의 네이티브 세로 탭 UI(브라우저 크롬 영역)에 접근하거나 주입할 수 없다. Side Panel이 확장 프로그램이 가질 수 있는 가장 가까운 대안이다.
- `chrome.sidePanel.open()`은 사용자 제스처(툴바 아이콘 클릭 등) 없이 호출할 수 없다. 브라우저 재시작 후에는 매번 최초 1클릭이 필요하며, 이를 우회할 방법은 없다.
- Side Panel의 최소 폭은 Chrome에 하드코딩된 약 320px이며, 이 아래로는 줄일 수 없다.
- Side Panel의 폭은 세션 중에는 자유롭게 조절되지만 브라우저 재시작 시 기본값(약 360px)으로 초기화되고, Chrome이 폭을 영구 저장해주지 않는다.
- 왼쪽 배치 여부는 확장 프로그램이 아니라 사용자가 Chrome 자체 설정(설정 > 모양 > 사이드패널 > 왼쪽)에서 지정한다.

검토했던 대안(별도의 도킹 창을 `chrome.windows`로 직접 구현하는 방식)은 위 제약들을 일부 회피할 수 있지만, 메인 브라우저 창과 별도 창의 위치/크기를 계속 동기화해야 해서 구현 복잡도와 불안정성이 크게 높아진다고 판단해 채택하지 않았다.

## 프로젝트 구조

```
bookmark-sidepanel/
├── manifest.json
├── background.js
├── sidepanel/
│   ├── sidepanel.html
│   ├── sidepanel.js
│   └── sidepanel.css
├── icons/
├── docs/
│   └── specs/
│       └── 2026-09-14-bookmark-sidepanel-design.md
└── README.md
```

빌드 도구 없이 순수 HTML/CSS/JS(바닐라)로 구성한다. 이 규모의 확장 프로그램에 프레임워크 도입은 과설계다.

## 컴포넌트 & 데이터 흐름

**background.js (서비스 워커)**
- `chrome.runtime.onInstalled`에서 `chrome.sidePanel.setPanelBehavior({ openPanelOnActionClick: true })` 설정 한 줄만 담당.

**sidepanel.js**
- 초기 로드 시 `chrome.bookmarks.getTree()`로 전체 트리를 가져와 재귀적으로 폴더/북마크 DOM을 렌더링.
- 폴더 클릭 시 펼침/접힘 토글 (상태는 메모리에만 유지).
- 북마크 클릭 시 `chrome.tabs.create({ url })`로 새 탭에서 열기.
- 검색창 입력 시 트리를 평탄화한 리스트에서 제목/URL로 필터링해 매칭 결과만 표시 (트리 유지 + 폴더 숨김 방식보다 단순함).
- 추가: 현재 탭을 북마크로 저장하는 버튼 → `chrome.bookmarks.create()`.
- 삭제: 항목별 삭제 버튼 → `chrome.bookmarks.remove()` (자식이 있는 폴더는 `removeTree()`).
- 이동: HTML5 드래그앤드롭 이벤트로 순서/폴더 변경 감지 → `chrome.bookmarks.move()`.
- `chrome.bookmarks.onCreated/onRemoved/onChanged/onMoved` 리스너로 외부 변경 시 트리 다시 렌더링.

## 권한 (manifest.json)

```json
{
  "permissions": ["bookmarks", "sidePanel"]
}
```

`tabs` 권한은 필요 최소화를 위해 요청하지 않고, `chrome.tabs.create`만 사용 (해당 API는 `tabs` 권한 없이도 호출 가능).

## 에러 처리

- `chrome.bookmarks` API 호출 실패(자식이 있는 폴더를 잘못된 방식으로 삭제 시도, 자기 자신 하위로 이동 시도 등)는 try/catch로 잡아 패널 하단에 짧은 에러 메시지를 표시. 확장 프로그램 전체를 중단시키지 않는 선에서 최소한으로만 처리한다.
- 빈 상태: 북마크가 없을 때, 검색 결과가 없을 때 각각 안내 문구를 표시한다.

## 검증 방법

테스트 인프라가 없는 브라우저 확장 프로그램이므로 수동 검증으로 진행한다.

1. `chrome://extensions` → 압축해제된 확장 프로그램 로드
2. 실제 북마크와 트리가 일치하는지, 검색/추가/삭제/이동이 `chrome://bookmarks`에도 반영되는지 확인
3. 사이드패널 크기 조절 시 페이지가 실제로 리플로우되는지 확인
4. 브라우저 재시작 후 1클릭으로 재오픈되는지, 폭이 기본값으로 초기화되는지 확인 (설계상 예상된 동작)

## 배포

v1은 로컬 개발자 모드(압축해제된 확장 프로그램)로 사용한다. Chrome 웹스토어 공개 배포는 추후 검토 대상이며, 그 시점에 아이콘 세트, 스토어 설명, 개인정보 처리방침 등을 별도로 준비한다. 권한은 이번 설계 단계부터 최소화(`bookmarks`, `sidePanel`만 요청)해 향후 심사 리스크를 낮춘다.
